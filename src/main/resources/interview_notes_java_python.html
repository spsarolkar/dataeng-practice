1. Data Structures (Java & Python)

A refresher on core structures using examples from your project dataeng-practice.

Java Collections

  • List (ArrayList vs LinkedList): Ordered collection. ArrayList is fast for access (O(1)), slow for inserts/removes in middle. LinkedList is opposite.
    Project Example: In IotSensorSpikeDetector.java, you use List<String> alerts = new ArrayList<>() to store multiple alert messages generated in a single stream batch.
  • Map (HashMap vs LinkedHashMap vs TreeMap): Key-Value pairs.
    • HashMap: O(1) access. Unordered.
    • LinkedHashMap: Preserves insertion order. Used in your LRUCache.java example!
    • TreeMap: Sorted by keys (O(log n)).

    Project Example: In LRUCache.java, you extend LinkedHashMap<Integer,Integer> and override removeEldestEntry to implement a cache eviction policy automatically.
  • Set (HashSet): Unique elements. O(1) access. Important for deduplication tasks.

Python Data Structures

You didn't have Python files in the specific repo, but here is the cheat sheet:

  • list: Dynamic array. my_list = [1, 2, 3]. Slicing list[::] is very powerful.
  • dict: Hash table. my_dict = {"key": "value"}. Highly optimized in Python 3.6+ (ordered by insertion).
  • set: Unique keys. my_set = {1, 2, 3}. Great for set(list_a) & set(list_b) (intersection).
  • tuple: Immutable list. my_tuple = (1, 2). Used as keys in dicts.

2. Java Core (8+) & Concurrency

Functional Programming (Streams)

Concurrency & Multithreading

  • Threads vs Executers: Don't use raw Thread. Use ExecutorService.
  • CompletableFuture: For non-blocking async programming (similar to JavaScript Promises).
  • Synchronization: synchronized keyword vs ReentrantLock vs AtomicInteger.
  • Spark Parallelism: In your project, Spark handles concurrency distributedly. mapToPair and reduceByKey run in parallel across nodes/cores. Mentioning this shows you understand "Distributed Concurrency".

JVM Internals

  • Memory Model: Heap (Objects) vs Stack (Primitives/References).
  • GC (Garbage Collection): G1GC (default now), Parallel GC. Explain "Stop-The-World" events and how to tune them (briefly).
